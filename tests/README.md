# فحوص «كشف المتابعة الإلكتروني»

برامج صغيرة تفحص التطبيق تلقائيًا قبل كل تحديث، بدل الفحص بالعين. كل فحصٍ
هنا يحرس عطلًا وقع فعلًا أو كاد يصل إلى المعلّم.

**لا تؤثّر على التطبيق إطلاقًا.** الموقع يقرأ `index.html` وحده، وهذا المجلد
لا يصل إلى المتصفّح.

## التشغيل

```
node tests/run.js            # كل الفحوص
node tests/run.js sync       # ملفات اسمها يحوي sync وحدها
```

يخرج برمز ١ إن سقط فحصٌ واحد.

فحوص المتصفّح تحتاج Playwright. بدونه تُتخطّى بوضوح ولا تُسقط البقيّة:

```
npm i -D playwright && npx playwright install chromium
```

إن كان المتصفّح في مكانٍ غير معتاد: `CHROME_PATH=/path/to/chrome node tests/run.js`

## الملفات

| الملف | ما يحرسه |
|---|---|
| `harness.js` | يُشغّل التطبيق خارج المتصفّح: يقرأ `index.html`، ويستخرج كتل `<script>`، ويُشغّلها مع بدائل مبسّطة لما يوفّره المتصفّح. ليس فحصًا بنفسه. |
| `t-sync.js` | **الحفظ والمزامنة** — أخطر ما في التطبيق، وهنا يضيع عمل المعلّم إن أخطأنا. طلبان متداخلان، تعديلٌ أثناء الرفع، جوابٌ ضاع بعد أن كتب الخادم، خروجٌ من التطبيق ثم عودة، والتضارب الحقيقي. |
| `t-reports.js` | **التقارير التي تخرج إلى غيرنا** — ورقة المرشد وورقة ولي الأمر. رقمٌ خاطئ فيها يُبنى عليه قرار، ولا تُراجَع قبل إرسالها. |
| `t-style.js` | **قواعد التنسيق التي تُفسد ورقة** — قصّ الأسماء، ثبات الترويسة، ارتفاع السطر على الورق، وأزرار المحو التي يجب ألّا تبدو كأزرار تأكيد. |
| `t-layout.js` | **قياسٌ في متصفّح حقيقي** — ما لا يُعرف إلا بالتخطيط الفعلي: هل يُقصّ اسم؟ هل تثبت الترويسة؟ كم صفحة يخرج الكشف؟ هل يقفز المعلّم لأعلى بعد كل رصدة؟ |

## عند إضافة فحص

- اكتب **سبب** الفحص بجانبه، لا ما يفعل فقط. الفحص بلا سببٍ يُحذف عند أول
  إزعاج، والسبب هو ما يمنع عودة العطل.
- بعد كتابة الفحص، **انزع الإصلاح وتأكّد أنه يسقط**. فحصٌ ينجح في الحالتين
  لا يحرس شيئًا — وقد مرّ علينا هذا.
- قِس ولا تفترض. «يبدو صحيحًا» ليست نتيجة.
